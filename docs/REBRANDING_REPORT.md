# Rebranding Report — VoltReport → VoltHub

**Date:** 2026-06-05
**Scope:** Rename all *user-facing* references from **VoltReport** to **VoltHub**, making VoltHub the primary application identity.
**Guarantees honored:** No database schema changes · No API contract changes · No route breakage · No persisted-state breakage.

---

## 1. Strategy

The rebrand was applied to **user-facing surfaces only** (browser titles, app/portal branding, manifests, mobile display name, generated documents). **Technical identifiers were intentionally preserved** because renaming them would be a breaking change with no user-visible benefit:

- `localStorage` / IndexedDB keys → renaming would log users out and discard saved drafts/preferences.
- Native `appId` (`id.pln.voltreport`) → renaming breaks app-store identity, signing, and existing installs.
- Database / test-DB names → excluded by the "no schema change" rule.
- Package name `voltreport`, import paths, Sentry release slugs → internal, non-visible.

The FE web app was **already** branded as VoltHub via a single source of truth ([FE/src/lib/brand.ts](../FE/src/lib/brand.ts), `BRAND_NAME = "VoltHub"`), consumed by the login page, sidebar, dashboard, and browser title. Remaining hardcoded "VoltReport" strings lived mostly in the **distribution portal** and the **backend-generated documents**.

These are **deliberately kept** to satisfy the no-breaking-changes / no-schema / no-API-contract rules.

## 5. Manual Actions Required

1. **External domain** — `APP_URL = "https://app.voltreport.id"` in [portal/src/routes/index.tsx](../portal/src/routes/index.tsx) and [portal/src/components/AppShell.tsx](../portal/src/components/AppShell.tsx) points the "Masuk Aplikasi" button at the live app. If the production domain is migrated to `app.volthub.id`, register/redirect it first, then update these two constants. Left unchanged here to avoid pointing at an unregistered host.

2. **Native app store identity** — `appId: "id.pln.voltreport"` and store URLs (`play.google.com/...id=id.pln.voltreport`, `apps.apple.com/app/voltreport` in [BE/src/config/env.ts](../BE/src/config/env.ts)). Changing the package ID requires a **new** store listing + signing key and breaks existing installs/updates. Treat as a separate release decision.

3. **Rebuild artifacts** — run `npm run build` in `FE/`, `portal/`, and `BE/` so the regenerated `dist/` reflects the new branding (PWA manifest, portal HTML, etc.).

4. **Icon/branding assets (optional)** — `favicon.svg`, `icon-192.png`, `icon-512.png` keep neutral filenames and require no rename, but the artwork should be refreshed to the VoltHub mark if a new logo exists.

5. **Storage-key migration (optional, only if a clean break is wanted)** — if you ever want the `voltreport-*` localStorage/IndexedDB keys renamed to `volthub-*`, ship a one-time migration that copies old keys to new ones on first load; do **not** rename them in place without it.
