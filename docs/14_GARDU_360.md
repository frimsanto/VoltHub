# 14 — GARDU 360 SPECIFICATION

**Product:** VoltHub V2
**Version:** 1.0
**Status:** Core Screen Definition
**Source:** `dokumen_lengkap/GARDU 360 SPECIFICATION.docx`
**Route:** `/gardu/:id`

---

## Purpose

Gardu 360 is the **center of all operational activity** in VoltHub. All data related to a Gardu must be accessible from a single page. This is the primary screen of the entire application.

---

## Header Section

**Display:** Kode Gardu, Nama Gardu, RTUPP, UP3, Penyulang.

**Status Badges:** RC Status (`INSCAN`/`OOP`/`UNKNOWN`), VIP Status (`VIP`/`VVIP`/`NON_VIP`), Operational Status (`ACTIVE`/`INACTIVE`/`MAINTENANCE`).

**Quick Actions:** Create Inspection · Create HAR · Create Ticket · Upload Document.

---

## Tabs

### TAB 1 — OVERVIEW
- **Information:** Site Profile, Location, Coordinate, Description
- **KPIs:** Total Asset, Total Inspection, Total HAR, Open Ticket

### TAB 2 — ASSETS
- **Table:** Asset Number, Type, Serial Number, Brand, Condition
- **Actions:** Add Asset, Edit Asset

### TAB 3 — INSPECTIONS
- **History Table:** Date, Inspector, Status, Findings
- **Actions:** Create Inspection, View Detail

### TAB 4 — HAR
- **History Table:** Date, Technician, Status
- **Actions:** Create HAR, View Detail

### TAB 5 — PERFORMANCE
- **Charts:** Daily Trend, Monthly Trend, Availability
- **Metrics:** Current Score, Last 30 Days Score

### TAB 6 — TICKETS
- **Table:** Ticket Number, Category, Priority, Status
- **Actions:** Create Ticket

### TAB 7 — DOCUMENTS
- **Files:** Photos, PDFs, Excel, Drawings
- **Actions:** Upload, Download

### TAB 8 — AUDIT LOG
- **History:** User, Action, Timestamp
- **Read-only** (per BR-018).

---

## Design Principle

The user must be able to answer:

1. **Apa kondisi Gardu ini?** — What is the condition of this Gardu?
2. **Apa masalah terakhirnya?** — What was its latest problem?
3. **Apa yang sudah dikerjakan?** — What has already been done?
4. **Apa yang harus dilakukan selanjutnya?** — What must be done next?

---

## Data Sources per Tab (implementation reference)

| Tab | Backing data | API |
|-----|--------------|-----|
| Overview | `sites` + aggregate counts | `GET /api/sites/{id}` ([15_API_SPEC.md](15_API_SPEC.md), API-002) |
| Assets | `assets` where `site_id` | `GET /api/sites/{id}/assets` |
| Inspections | `inspections` where `site_id` | `GET /api/sites/{id}/inspections` |
| HAR | `har_records` where `site_id` | `GET /api/sites/{id}/har` |
| Performance | `performance_daily` where `site_id` | `GET /api/sites/{id}/performance` |
| Tickets | `tickets` where `site_id` | `GET /api/sites/{id}/tickets` |
| Documents | `attachments` where `entity_type=site` | `GET /api/sites/{id}/attachments` |
| Audit Log | `audit_logs` where `entity_type=site` | `GET /api/sites/{id}/audit` |

> Per-tab sub-resource endpoints are derived from the API-002 aggregate summary; explicit per-tab endpoints are **not enumerated** in the source API spec and are proposed here for development. Quick Actions map to API-003 (Inspection), API-004 (HAR), Ticket create, and attachment upload. **Mobile-friendly required** (PRD §18).
